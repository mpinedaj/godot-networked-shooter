Armar la red LAN–WAN–LAN con dos routers Cisco y dos PC

Paso a paso: conectarse al router por el cable de consola con PuTTY, configurar las interfaces, cablear, poner la IP en los PC y jugar. Al final, cómo hacer lo mismo con los scripts del proyecto.

Los pasos

  1. Tener los materiales listos
  2. Conectar el cable de consola y ver el puerto COM
  3. Abrir PuTTY (aquí va el 9600)
  4. Entrar al router y ver sus interfaces
  5. Configurar el Router A
  6. Configurar el Router B
  7. Conectar los cables Ethernet
  8. Poner la IP en cada PC
  9. Verificar con ping y tracert
  10. Jugar
  11. Si algo falla
  12. Atajo: los scripts del proyecto

1Materiales

  • Dos routers Cisco (cualquier modelo con dos puertos Ethernet; por ejemplo 1841, 1941, 2901 o 2911).
  • Dos PC con Windows y puerto Ethernet, con el juego y PuTTY instalados.
  • Un cable de consola: el azul celeste que va del puerto CONSOLE del router al USB del PC (RJ-45 a USB, o RJ-45 a serie DB9 con un adaptador USB). Algunos routers traen además un puerto de consola mini-USB.
  • Tres cables Ethernet: PC host–Router A, Router A–Router B y Router B–PC cliente.
Cable entre los routers

Los routers con puertos Gigabit (G0/0) se arreglan solos con cualquier cable Ethernet. Si los routers son viejos, con puertos FastEthernet (Fa0/0), el cable router–router debe ser cruzado (como en Packet Tracer). Los cables PC–router son normales (directos). Si una luz no prende, prueben con el otro tipo de cable.

Wi-Fi apagado

Durante la práctica, desconecten el Wi-Fi de los dos PC. Muchas redes Wi-Fi usan direcciones 192.168.1.x, iguales a las de la LAN A, y Windows puede mandar los paquetes por el Wi-Fi en vez de por el cable.

2El cable de consola y el puerto COM

El cable de consola no es de red: es una conexión serie, como un teclado y una pantalla conectados directo al router. Sirve para configurarlo cuando todavía no tiene ninguna IP.

  1. Conecten el extremo RJ-45 al puerto CONSOLE del router (suele estar en la parte de atrás, marcado en azul celeste) y el USB al PC.
  2. Enciendan el router (interruptor atrás). Los ventiladores arrancan y las luces parpadean un rato.
  3. En el PC abran el Administrador de dispositivos: clic derecho en el botón Inicio → Administrador de dispositivos.
  4. Desplieguen Puertos (COM y LPT). Debe aparecer algo como USB Serial Port (COM3) o Prolific USB-to-Serial Comm Port (COM4).
Este es “el número que hay que poner”

El COM3 (o el número que les salga) es lo que va en PuTTY en Serial line. Cambia de un PC a otro y de un puerto USB a otro, por eso hay que mirarlo aquí cada vez.

Si no aparece “Puertos (COM y LPT)” o sale un dispositivo con un triángulo amarillo, falta el controlador del cable: búsquenlo por la marca del adaptador (Prolific, FTDI, CH340) o, si es el puerto mini-USB del router, el “Cisco USB Console Driver”.

Lo único que normalmente hay que cambiar es Flow control: PuTTY trae XON/XOFF y debe quedar en None. Pueden volver a Session, escribir un nombre en Saved Sessions y pulsar Save para no repetirlo. Por último, Open: se abre una ventana negra.

Configuración completa

COM3 · 9600 · 8 bits de datos · sin paridad · 1 bit de parada · sin control de flujo. A veces se escribe abreviado como 9600 8N1.

4Entrar al router y ver sus interfaces

En la ventana negra de PuTTY pulsen Enter un par de veces. Según cómo esté el router, verán una de estas cosas:

Would you like to enter the initial configuration dialog? [yes/no]: no      ← escriban no y Enter
Press RETURN to get started!                                         ← Enter
Router>

El símbolo del final dice en qué modo está el router:

PromptModoCómo se entra / se sale
Router>Usuario: solo mirar lo básico.Es donde se empieza.
Router#Privilegiado: ver todo, guardar, hacer ping.enable · se vuelve con disable
Router(config)#Configuración general.configure terminal · se sale con end
Router(config-if)#Configurando una interfaz.interface … · se sale con exit

Entren al modo privilegiado y miren las interfaces:

Router> enable
Router# show ip interface brief
Interface                  IP-Address      OK? Method Status                Protocol
Embedded-Service-Engine0/0 unassigned      YES unset  administratively down down
GigabitEthernet0/0         unassigned      YES unset  administratively down down
GigabitEthernet0/1         unassigned      YES unset  administratively down down
GigabitEthernet0/2         unassigned      YES unset  administratively down down
  • Los nombres de la primera columna son los que se usan en los comandos. En un 2911 son GigabitEthernet0/0, 0/1…; en un 1841 son FastEthernet0/0 y FastEthernet0/1. Si los suyos son distintos, cámbienlos en los comandos de los pasos 5 y 6.
  • En la parte de atrás del router, cada puerto Ethernet está marcado con su número (GE 0/0, GE 0/1, o FE 0/0…). Así saben dónde va cada cable.
  • administratively down significa “apagado a propósito”: los puertos de un router vienen apagados hasta que se les da no shutdown.
  • Embedded-Service-Engine es interna: no se usa.
Si pide contraseña o ya tiene configuración

Si al escribir enable pide Password, se la piden al profesor. Si el router ya tiene IPs de otro grupo, pueden verlas con show running-config; los comandos de esta guía les ponen encima las suyas. No borren la configuración del router (write erase) sin preguntar.

5Configurar el Router A (el del PC host)

Con PuTTY conectado al Router A, escriban esto línea por línea. Lo que va después de ! es explicación, no lo escriban. Se puede pegar en PuTTY con clic derecho.

Router# configure terminal
hostname RouterA                        ! le pone nombre (cambia el prompt)
no ip domain-lookup                     ! si escriben mal un comando, no se queda "buscándolo"
line console 0
 logging synchronous                    ! los avisos no cortan lo que están escribiendo
 exit
interface GigabitEthernet0/0            ! el puerto que va al PC host (LAN A)
 description LAN A - PC host
 ip address 192.168.1.1 255.255.255.0   ! la puerta de enlace del PC host
 no shutdown                            ! encender el puerto
 exit
interface GigabitEthernet0/1            ! el puerto que va al Router B (WAN)
 description WAN hacia RouterB
 ip address 10.0.0.1 255.255.255.252    ! /30: solo dos direcciones, una por router
 no shutdown
 exit
ip route 192.168.2.0 255.255.255.0 10.0.0.2   ! "para llegar a la LAN B, mándalo al Router B"
end
RouterA# write memory                     ! guardar (opcional; preguntar al profe)

Después de cada no shutdown puede aparecer un aviso como %LINK-3-UPDOWN … changed state to down. Es normal mientras no haya cable: el puerto ya está encendido, pero no tiene nada conectado.

6Configurar el Router B (el del PC cliente)

Cierren PuTTY, pasen el cable de consola al Router B (el número COM es el mismo si usan el mismo PC y el mismo USB) y vuelvan a abrir PuTTY. Los comandos son los mismos, pero con las direcciones del otro lado:

Router# configure terminal
hostname RouterB
no ip domain-lookup
line console 0
 logging synchronous
 exit
interface GigabitEthernet0/0
 description LAN B - PC cliente
 ip address 192.168.2.1 255.255.255.0
 no shutdown
 exit
interface GigabitEthernet0/1
 description WAN hacia RouterA
 ip address 10.0.0.2 255.255.255.252
 no shutdown
 exit
ip route 192.168.1.0 255.255.255.0 10.0.0.1   ! "para llegar a la LAN A, mándalo al Router A"
end
RouterB# write memory
Lo único que cambia entre A y B

El nombre, la IP de la LAN (.1.1 ↔ .2.1), la IP de la WAN (10.0.0.1 ↔ 10.0.0.2) y la ruta: cada router apunta a la LAN del otro, a través de la IP WAN del otro.

7Conectar los cables Ethernet

CableDesdeHasta
1PC host, puerto EthernetRouter A, G0/0 (LAN)
2Router A, G0/1 (WAN)Router B, G0/1 (WAN) — cruzado si son FastEthernet
3Router B, G0/0 (LAN)PC cliente, puerto Ethernet

Cuando un cable está bien, se encienden las luces del puerto en los dos extremos. En PuTTY aparece %LINEPROTO-5-UPDOWN: Line protocol on Interface GigabitEthernet0/0, changed state to up.

8Poner la IP en cada PC

En cada PC: Configuración → Red e Internet → Ethernet → Asignación de IP → Editar → Manual → IPv4 activado. También sirve el camino clásico: Win+R, ncpa.cpl, clic derecho en Ethernet → Propiedades → Protocolo de Internet versión 4 (TCP/IPv4) → Usar la siguiente dirección IP.

PC cliente
Dirección IP192.168.2.10
Máscara255.255.255.0
Puerta de enlace192.168.2.1
DNSvacío

Firewall de Windows. Por defecto Windows no responde al ping y puede bloquear el juego. En cada PC, abran PowerShell como administrador y escriban:

New-NetFirewallRule -DisplayName "LAN Shooter - ping" -Direction Inbound -Protocol ICMPv4 -IcmpType 8 -Action Allow
New-NetFirewallRule -DisplayName "LAN Shooter - juego UDP 9999" -Direction Inbound -Protocol UDP -LocalPort 9999 -Action Allow

Si la primera vez que abren el juego Windows pregunta si permite el acceso a la red, acepten en redes privadas y públicas (una red sin internet suele quedar como “pública”).

9Verificar

En cada router (PuTTY)

RouterA# show ip interface brief
GigabitEthernet0/0   192.168.1.1   YES manual up                    up
GigabitEthernet0/1   10.0.0.1      YES manual up                    up
RouterA# show ip route
C    10.0.0.0/30 is directly connected, GigabitEthernet0/1
C    192.168.1.0/24 is directly connected, GigabitEthernet0/0
S    192.168.2.0/24 [1/0] via 10.0.0.2              ! la ruta estática
RouterA# ping 10.0.0.2                      ! el otro router
!!!!!
RouterA# ping 192.168.2.10                  ! el PC cliente
!!!!!

En el ping de un router, cada ! es una respuesta y cada . una que no llegó. Es normal que el primer ping salga .!!!!: el router está averiguando la dirección física (ARP) del vecino.

En los PC (Símbolo del sistema o PowerShell)

C:\> ping 192.168.1.1            ! desde el host: su router
C:\> ping 192.168.2.10           ! desde el host: el cliente, cruzando los dos routers
Respuesta desde 192.168.2.10: bytes=32 tiempo=1ms TTL=126
C:\> tracert 192.168.2.10
  1    <1 ms   192.168.1.1
  2     1 ms   10.0.0.2
  3     1 ms   192.168.2.10

El TTL=126 confirma que el paquete pasó por los dos routers: Windows lo manda con 128 y cada router le resta uno. El tracert muestra los saltos: el Router A, el Router B (por su IP WAN) y el otro PC.

10Jugar

  1. En el PC host: abrir el juego, escribir un nombre y Crear partida (Host). El menú muestra “Tu IP en la red local: 192.168.1.10”.
  2. En el PC cliente: nombre, IP 192.168.1.10, puerto 9999, Unirse.
  3. El host ve al cliente en la sala de espera y pulsa Iniciar partida.
  4. Con F3, el cliente ve “Servidor: 192.168.1.10:9999” y la latencia real a través de los dos routers. Es la captura ideal para el informe (sección “Prueba con equipos físicos”).

11Si algo falla

Vayan del equipo más cercano al más lejano: primero el PC con su router, luego entre routers y al final el otro PC.

Qué pasaQué revisar
PuTTY abre la ventana negra pero no sale nadaPulsar Enter varias veces; revisar que el router esté encendido, que el cable esté en CONSOLE (no en un puerto Ethernet) y que el COM sea el del Administrador de dispositivos.
Salen símbolos rarosLa velocidad no es 9600 (o alguien la cambió en el router).
PuTTY dice “Unable to open connection to COM3”El número COM es otro, o el puerto está abierto en otra ventana de PuTTY o en el script.
% Invalid input detected en interface …El nombre de la interfaz no existe en ese modelo: usen el que mostró show ip interface brief.
Interfaz administratively downFalta no shutdown dentro de esa interfaz.
Interfaz down downEl cable no está, está en otro puerto, o es del tipo equivocado (cruzado/directo). El equipo del otro lado debe estar encendido.
El PC no hace ping a su routerIP o máscara del PC mal escritas, el cable va a otro puerto del router, o el Wi-Fi está usando la misma red (apáguenlo).
Un router no hace ping al otroLas IP WAN deben ser 10.0.0.1 y 10.0.0.2 con máscara 255.255.255.252; revisar el cable entre routers.
El PC llega a su router pero no al otro PCFalta la ruta estática en algún router (show ip route debe tener la S), falta la puerta de enlace en algún PC, o el firewall del otro PC bloquea el ping.
El ping funciona pero el juego no conectaFirewall del PC host: falta permitir UDP 9999. Revisar que el cliente escriba 192.168.1.10 y el puerto 9999.

Al terminar la práctica

  • En los PC: volver a poner la IP en Obtener una dirección IP automáticamente, borrar las dos reglas del firewall y volver a encender el Wi-Fi.
  • En los routers: si guardaron con write memory, la configuración queda aunque los apaguen. Si el profesor pide dejarlos limpios: write erase y luego reload (contestar no si pregunta si guarda).

Anexo: si los routers se unen por un cable serie

Si en lugar de Ethernet el profesor les da un cable serie entre los routers (interfaces Serial0/0/0), cambia la WAN: en los dos routers se usa interface Serial0/0/0 con las mismas IP 10.0.0.x, y solo en el router donde está el extremo DCE del cable se agrega clock rate 64000. Para saber cuál es: show controllers serial 0/0/0 dice DCE o DTE. El script lo hace solo si le dicen que la WAN es Serial0/0/0.

12Atajo: los scripts del proyecto

En la carpeta tools del repositorio hay dos scripts que hacen exactamente lo de los pasos 5, 6 y 8. Sirven para no escribir todo a mano el día de la prueba, pero conviene haberlo hecho una vez con PuTTY para poder explicarlo en la sustentación.

Configurar un router: tools\configurar-router.bat

  1. Conecten el cable de consola al router y cierren PuTTY (el puerto COM solo lo puede usar un programa a la vez).
  2. Doble clic en configurar-router.bat. Pregunta si es el Router A o el B.
  3. Encuentra solo el puerto COM (si hay varios, pregunta cuál), lo abre a 9600 8N1 sin control de flujo, pulsa Enter, contesta “no” al asistente inicial y entra a enable.
  4. Lee show ip interface brief y propone cuál puerto es la LAN y cuál la WAN. Con Enter se acepta; con n se escriben a mano.
  5. Envía los comandos del paso 5 o 6, avisa si el router rechaza alguno y pregunta si guardar con write memory.
  6. Verifica: que las interfaces estén up/up, que esté la ruta estática y si el otro router responde al ping.
== Despertando el router (Enter)
   !!  El router ofrece el asistente inicial: se contesta "no".
   OK  Router listo en modo privilegiado (#).
Propuesta:  LAN (cable al PC) = GigabitEthernet0/0    WAN (cable al otro router) = GigabitEthernet0/1
¿Es correcto? Enter = sí, n = escribirlas yo:
== Configurando el RouterA
   OK  El router aceptó todos los comandos.
   OK  GigabitEthernet0/0 está up/up.
   OK  Ruta estática hacia 192.168.2.0/24 presente.

Lo que respondió el router queda guardado en tools\registros\: sirve como evidencia para el informe.

Configurar un PC: tools\configurar-pc.bat

  1. Doble clic y elegir 1 = host, 2 = cliente o 3 = restaurar. Windows pide permiso de administrador.
  2. Pone la IP del paso 8 en el adaptador Ethernet, agrega las rutas hacia la otra LAN por su router y abre el firewall para el ping y el UDP 9999.
  3. Avisa si el Wi-Fi está usando la misma red y prueba ping al router y al otro PC.
  4. Con 3 = restaurar deja el Ethernet en automático y borra las reglas del firewall.
Una diferencia con el paso 8

El script no pone “puerta de enlace”: agrega dos rutas (hacia la otra LAN y hacia la WAN) que pasan por el router. El resultado para el juego es el mismo, pero así el PC no pierde el internet de otra conexión si la tiene.

Si Windows no deja ejecutarlo

Si sale un aviso azul de “Windows protegió su PC”: Más información → Ejecutar de todas formas. Si dice que la ejecución de scripts está deshabilitada, usen siempre los .bat, que ya lo resuelven.
